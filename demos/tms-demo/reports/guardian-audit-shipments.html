Guardian Audit — Shipments (TMS)

A two-panel TMS operator view: a shipments data table on the left, a details tile on the right that opens on row selection. Built so a dispatcher can spot a delayed lane (TMS-4798, Dallas → LA), read its lane rate and ETA slip, and approve the route or pull up the map.

📐 Step 1 — Derived design spec
Interactive elements above fold5 in the calm state — table title, table body (6 selectable rows as one region), a single "+ New" toolbar action, and the empty details tile. Within the ≤ 6 threshold.
Actions — calm stateSelect a shipment row (primary path) · optional "+ New". No competing call-to-action.
Actions — selection state"Approve route" (primary) · "View on map" (secondary) · close details. One dominant primary action.
Persistent decorative elementsNone. No ticker, feed, sparkline, or status band above the table.
Empty / calm stateDetails tile shows an instructional empty state ("Select a shipment / Click any row to see details").
Ambiguities affecting the audit"+ New" toolbar button is implied by the layout but not in the brief — counted as one secondary action. "Approve route" is a route-level commitment; whether it needs a confirmation step is flagged to the Interaction agent (I3).
